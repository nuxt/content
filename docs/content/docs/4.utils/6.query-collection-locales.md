## Usage

Use the auto-imported `queryCollectionLocales` to list every translation of a content item, for example to build a language switcher or `hreflang` links. It works with collections that have the [`i18n` option](/docs/integrations/i18n) and returns every locale, whatever the active locale is.

```vue [components/LanguageSwitcher.vue]
<script setup lang="ts">
import type { Locale } from 'vue-i18n'

const route = useRoute()
const { locale } = useI18n()
const localePath = useLocalePath()

const path = computed(() => route.path.replace(new RegExp(`^/${locale.value}(?=/|$)`), '') || '/')

const { data: translations } = await useAsyncData(
  () => `translations:${path.value}`,
  async () => {
    const page = await queryCollection('docs').path(path.value).first()
    return page ? queryCollectionLocales('docs', page.stem) : []
  },
)
</script>

<template>
  <nav>
    <NuxtLink
      v-for="translation in translations"
      :key="translation.locale"
      :to="localePath(translation.path, translation.locale as Locale)"
    >
      {{ translation.title }}
    </NuxtLink>
  </nav>
</template>
```

::warning
The returned `path` has no locale prefix and is the same for every translation. Pass it with the locale to the function returned by `useLocalePath()` to get the URL of a translation.
::

::tip
The `queryCollectionLocales` utility is available in both Vue and Nitro. See [Server Usage](#server-usage) to use it on the server side.
::

## Type

```ts
function queryCollectionLocales<T extends keyof PageCollections>(
  collection: T,
  stem: string
): Promise<Required<ContentLocaleEntry>[]>
function queryCollectionLocales<T extends keyof Collections>(
  collection: T,
  stem: string
): Promise<ContentLocaleEntry[]>

interface ContentLocaleEntry {
  locale: string
  stem: string
  // Set in page collections, and in other collections whose schema has the field
  path?: string
  title?: string
}
```

## API

### `queryCollectionLocales(collection: CollectionName, stem: string)`

List the translations of a content item.

- Parameters:
  - `collection`: The key of the defined collection in `content.config.ts`.
  - `stem`: The stem of the content item, for example `'docs/getting-started'`. Translations share the same stem.
- Returns: A promise that resolves to one entry per translation. A collection without the `i18n` option returns an empty array.

## Examples

### `hreflang` Links

`useLocaleHead()` from `@nuxtjs/i18n` adds alternate links for every locale of the current route. Build them from `queryCollectionLocales` instead when a page does not exist in every locale:

```vue [components/AlternateLinks.vue]
<script setup lang="ts">
import type { Locale } from 'vue-i18n'

const props = defineProps<{ stem: string }>()
const localePath = useLocalePath()
const { origin } = useRequestURL()

const { data: translations } = await useAsyncData(
  () => `translations:${props.stem}`,
  () => queryCollectionLocales('docs', props.stem),
)

useHead(() => ({
  link: (translations.value ?? []).map(translation => ({
    rel: 'alternate',
    hreflang: translation.locale,
    href: new URL(localePath(translation.path, translation.locale as Locale), origin).href,
  })),
}))
</script>
```

## Server Usage

Nuxt Content provides a similar utility to query collections on the server side. The only difference is that you need to pass `event` as the first argument to the `queryCollectionLocales` function.

```ts [server/api/translations.ts]
export default eventHandler(async (event) => {
  const { stem } = getQuery(event) as { stem: string }
  return await queryCollectionLocales(event, 'docs', stem)
})
```
